# Code Review Guidelines

## Purpose
- **Improve Code Quality**: Catch bugs early, ensure maintainability, and align with best practices.
- **Promote Collaboration**: Share knowledge, unify coding standards, and learn from each other.

## Key Principles
1. **Clarify the Goal**  
   - Understand the feature or bug fix thoroughly.  
   - Ask questions about requirements and constraints before reviewing.

2. **Focus on Clean Code and Architecture**  
   - Apply “Clean Code” principles (readability, simplicity, small functions).  
   - Keep architecture modular and aligned with “Clean Architecture” practices.

3. **Provide Constructive Feedback**  
   - Be specific about issues: logic errors, naming, structure, tests, etc.  
   - Suggest improvements with actionable steps.  
   - Acknowledge good solutions and highlight best practices.

4. **Review Promptly and Thoroughly**  
   - Don’t block progress: respond quickly to pull requests.  
   - Balance speed with depth—cover functionality, style, and possible edge cases.  
   - Keep comments concise and on-topic.

5. **Test Coverage and Documentation**  
   - Ensure new or changed code has adequate tests.  
   - Check if documentation (e.g., README, code comments) is updated.

6. **Handle Conflicts Calmly**  
   - Disagreements happen—keep discussions objective and solution-oriented.  
   - Seek common ground; escalate only when necessary.

7. **Merge with Confidence**  
   - Merge once feedback is addressed and tests pass.  
   - Keep the main branch stable and deploy-ready.

## Additional Best Practices
- **Automate Checks**: Use linters, formatters, and CI pipelines to catch common issues.
- **Consider Security**: Look for potential vulnerabilities, especially around data handling.
- **Optimize Performance**: Identify any bottlenecks or unnecessary complexity early.
- **Refactor When Needed**: If you see room for improvement, suggest incremental refactoring.

## Summary
A well-structured code review process clarifies goals, enforces quality standards, and fosters team growth. By following these guidelines, you ensure a more reliable, maintainable, and collaborative codebase.
